# Codebase Conventions

**Analysis Date:** 2026-08-15
**Scope:** Full Repository

This document outlines the coding standards, styling conventions, and architectural patterns used across the UIMS monorepo.

## Naming Patterns

- **Files and Directories**: 
  - Backend (API) and generic packages use `kebab-case` for all files (e.g., `users.controller.ts`, `create-user.dto.ts`).
  - Frontend (Web) uses `PascalCase` strictly for React component and page files (e.g., `PageContainer.tsx`, `NotFoundPage.tsx`), while using `kebab-case` for other utilities (e.g., `vitest.config.ts`).
- **Classes and Types**: `PascalCase` (e.g., `UsersService`, `CreateUserDto`).
- **Functions and Variables**: `camelCase` (e.g., `findAll`, `createUserDto`).
- **Constants**: Typically `UPPER_SNAKE_CASE` or `camelCase` depending on scope, but standard JS conventions apply.

## Code Style

Formatting and linting are strictly enforced via [Biome](file:///home/user/projects/uims/biome.json).

- **Indentation**: 2 spaces (`indentStyle: "space"`, `indentWidth: 2`)
- **Quotes**: Single quotes (`quoteStyle: "single"`)
- **Line Width**: 100 characters max
- **Semicolons**: Always required (`semicolons: "always"`)
- **Trailing Commas**: All (`trailingCommas: "all"`)
- **Arrays**: Generic array syntax is preferred over array literals (e.g., `Array<string>` instead of `string[]`). Enforced by Biome (`useConsistentArrayType: { syntax: "generic" }`).
- **Type Imports**: Inline types or standard imports are allowed (Biome's `useImportType` is disabled).

## Import Organization

- **Auto-organization**: Disabled in Biome (`assist.actions.source.organizeImports: "off"`). 
- Rely on standard logical grouping (external packages first, followed by internal absolute aliases like `@/components/...`, then relative imports).

## Error Handling

- **API (NestJS)**: Built-in HTTP exceptions are used uniformly (`NotFoundException`, `ConflictException`, `UnauthorizedException`). Avoid returning manual HTTP status objects in controllers.
- **Web (React)**: Standard `try/catch` logic within services and stores, usually propagated to UI boundaries like `ErrorBoundary.tsx`.

## Function and Module Design

- **API (NestJS)**: Feature-module driven design. Each entity (e.g., Users, Auth) has a dedicated folder under `apps/api/src/modules/` containing its `module`, `controller`, `service`, and `dto` definitions. Database interactions are abstracted using `PrismaService`.
- **Web (React)**: Layered architecture separating UI and state. Global state is managed via Zustand stores (`apps/web/src/stores/`). Pages are assembled in `apps/web/src/pages/`, composing smaller elements from `apps/web/src/components/`.
